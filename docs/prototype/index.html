标注说明

  1. 1连接状态：常驻顶栏，实时反映 /api/health，点击直达诊断。
  2. 2当前页面：active tab 的标题与 URL；☆ 标记重要。系统页显示“不采集”。

  6. 6历史排序概览：Top 5 + 四维评分构成条。
  7. 7整理建议摘要：归档 / 重复 / 保留计数。
  8. 8自然语言规则：输入后解析，跳到规则页确认保存。
  9. 9诊断入口：汇总检查结果。

验收演示路径

  1. 点「诊断」：后端连接、tabs、history 权限均为绿色
  2. 回首页点「同步浏览器上下文」→ 同步成功
  3. 看推荐（Actions 页面 + 理由）与排序 Top 5
  4. 「排序」页点开一行看评分明细
  5. 在规则框点示例 → 解析 → 确认保存
  6. 「整理」页：Issue 规则命中、docs.internal 被保留
  7. 右侧切到「离线」，观察降级与诊断排查提示

② 页面与状态一览

每个画面都是独立的可交互实例，覆盖正常、空、加载、异常和降级状态。编号与 PRD 第 5.3 节“画面清单”对应。

③ 信息架构与数据流

Popup 只负责展示和交互，所有浏览器 API 调用与后端通信都经过 Background Service Worker；后端负责存储、评分、推荐、整理和规则解析。

插件信息架构

  • Popup 弹窗（400 × 600）
    • 顶栏：品牌 · 后端连接状态（→ 诊断）
    • 当前页面卡片：标题 / URL / 标记重要
    • 同步条：同步按钮 · 时间 / 上传数 / 过滤数
    • 首页：推荐 Top 3 · 排序 Top 5 · 整理摘要 · 规则输入 · 诊断入口
    • 上下文：当前窗口标签页 · 最近历史（隐私标记）
    • 排序：公式图例 · 筛选 · 列表 · 评分明细
    • 整理：建议归档 · 疑似重复 · 建议保留 · 批量 / 撤销
    • 规则：输入 · 解析预览（确认 / JSON）· 已保存（启停 / 删除）
    • 诊断：总览 · 10 项检查 · API Base URL · 版本 · 复制报告
  • 右键菜单（contextMenus）
    • 添加到分析 · 标记为重要
  • Content Script（可选）
    • 在 GitHub / 文档页高亮推荐关键词与 issue 编号；chrome:// 页面跳过
